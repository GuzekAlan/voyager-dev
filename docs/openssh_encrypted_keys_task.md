# Passphrase-protected OpenSSH keys (openssh-key-v1 + bcrypt)

## Problem

OTP `:ssh_file` can't decrypt `openssh-key-v1` keys with a passphrase, which is what `ssh-keygen` writes by default (`-N`), for every key type including Ed25519. VOY-267 rejects these keys with "use SSH Agent or Password".

## PoC on this branch

`BcryptPbkdf` and `OpensshKey` are here, not yet wired into anything. Wiring them into `KeyFile` and the passphrase modal needs VOY-267 merged first.

Check them against keys from the local `ssh-keygen`: every cipher, ECDSA/RSA, and rounds 1, 2, 16 and the default, with the right and a wrong passphrase:

```sh
elixir -r lib/voyager/services/ssh/bcrypt_pbkdf.ex -r lib/voyager/services/ssh/openssh_key.ex \
  docs/openssh_key_matrix.exs /tmp/voyager-key-matrix
```

## Scope

- `Voyager.Services.SSH.BcryptPbkdf.derive/4`: bcrypt_pbkdf in pure Elixir (Blowfish state in `:atomics`, initial state computed from π at compile time).
- `Voyager.Services.SSH.OpensshKey.decrypt/2`: parse the container, derive key + IV, decrypt, verify (`checkint` pair, or the AEAD tag), rebuild an unencrypted container and decode it with `:ssh_file.decode/2`.
- Every cipher `ssh-keygen -Z` accepts:
  - `aes128/192/256-ctr`
  - `aes128/192/256-cbc`
  - `3des-cbc`
  - `aes128/256-gcm@openssh.com`
  - `chacha20-poly1305@openssh.com`
- Any number of KDF rounds; it is read from the key file.
- `KeyFile`:
  - an encrypted `openssh-key-v1` key is decrypted instead of returning `:key_encrypted_openssh`
  - `{:error, :key_passphrase_required}` without a passphrase, so the existing passphrase modal opens
  - `:key_bad_passphrase` on a wrong passphrase
  - `:key_unsupported_cipher` for anything else
- Decrypt once per connect: the modal check decodes the key and hands the decoded key to `key_cb`, instead of `user_key/2` decoding the file again.
- Run the decryption in `start_async` with a "Checking passphrase…" state in the modal; it takes ~105 ms per round on an M1 Pro (2.5 s at the `ssh-keygen` 10.3 default of 24 rounds), and grows linearly with `-a`.

## Out of scope

- DSA keys (OpenSSH 10 no longer generates them; `KeyFile` doesn't map `ssh-dss`)
- FIDO `-sk` keys (OTP can't sign with them)
- A native (NIF) bcrypt_pbkdf

## Acceptance

- Keys generated by `ssh-keygen` in `tmp_dir` decrypt and authenticate against `SshServer`:
  - Ed25519 with each of the ciphers above
  - ECDSA 256/384/521
  - RSA
  - rounds 1, 16 and the default
- A wrong passphrase gives `:key_bad_passphrase` for every cipher.
- The connect UI stays responsive while the key is being decrypted.
